`tui-test` lets you read the full terminal state at any point in a session, from plain text down to individual cell attributes, OSC 8 links, terminal modes, and retained scrollback rows.

## Read screen text, packed bytes, and cells

`text` returns the currently selected viewport (`full: false`, default) or all retained scrollback plus the live screen (`full: true`), trimming trailing spaces on each line. `packedScreen` returns exact terminal dimensions (`cols`, `rows`) alongside untrimmed UTF-8 rows separated by `\n`, preserving trailing spaces and blank rows (note that UTF-8 byte offsets differ from cell columns when wide or multibyte characters are present).

`cells(x, y, w, h)` reads a rectangular region in zero-based cell coordinates, including resolved colors, underline style and color, attribute flags, and OSC 8 link URI/ID metadata. `state` returns a single snapshot combining visible text, grid size, cursor, command status, exit code, terminal modes, mouse modes, colors, timeouts, readiness, and bell count.

## Individual state getters

When you only need one property, query it directly instead of fetching the full screen:

| Property | CLI `get` field | JavaScript | Python | Go |
| --- | --- | --- | --- | --- |
| Last shell command | `command` | `getCommand()` | `get_command()` | `GetCommand()` |
| Last command output | `output` | `getOutput()` | `get_output()` | `GetOutput()` |
| Last exit code | `exit-code` | `getExitCode()` | `get_exit_code()` | `GetExitCode()` |
| Working directory | `cwd` | `getCwd()` | `get_cwd()` | `GetCwd()` |
| Cursor position & style | `cursor` | `getCursor()` | `get_cursor()` | `GetCursor()` |
| Terminal modes | `modes` | `getModes()` | `get_modes()` | `GetModes()` |
| Default & palette colors | `colors` | `getColors()` | `get_colors()` | `GetColors()` |
| Grid dimensions | `size` | `getSize()` | `get_size()` | `GetSize()` |
| Scrollback viewport | `viewport` | `getViewport()` | `get_viewport()` | `GetViewport()` |
| Window title | `title` | `getTitle()` | `get_title()` | `GetTitle()` |

| Bell count & events | `bells`, `bell-events` | `getBellCount()`, `getBellEvents()` | `get_bell_count()`, `get_bell_events()` | `GetBellCount()`, `GetBellEvents()` |

## Navigate native scrollback history

Each session retains up to `profile.scrollback` rows above the live screen (10,000 rows by default). Native scrollback moves the emulator's inspection viewport without sending keystrokes or mouse wheel events to the child application.

- Positive line counts in `scroll(lines)` (`tui-test scroll up LINES`) move upward into older output; negative values (`tui-test scroll down LINES`) move back toward the live screen.
- `scrollToTop` (`scroll top`) jumps to the oldest retained row; `scrollToBottom` (`scroll bottom`) returns to the live screen (`offset == 0`).
- `getViewport` (`get viewport --json`) reports `{ offset, history }` in rows, where `offset` is how many rows above the live screen the viewport sits and `history` is total available scrollback rows.

<Tabs syncKey="example-language">

    ```js
    const olderScreen = await terminal.text();
    await terminal.scrollToBottom();
    console.log(viewport, olderScreen);
    ```
  </TabItem>

### How the history viewport interacts with other APIs

- Visible `text()`, visible locators, screenshots, raster recordings, and the live monitor all reflect the active scrollback viewport.
- `text({ full: true })` and `packedScreen({ full: true })` always read all retained scrollback plus the live screen regardless of `offset`.
- Incoming child output keeps your historical view pinned until those rows roll off the configured scrollback limit.
- Sending keyboard input automatically snaps the viewport back to the live screen. Sending mouse input or clicking a locator while `offset > 0` fails with a usage error; call `scrollToBottom` before clicking.
