## Text locators

Locators describe a query and resolve against the latest terminal screen before
each read or action. They do not hold a stale cell location.

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    console.log(await terminal.getByText("Save").locations());
    await terminal.getByText("Save").expect();
    await terminal.getByText("Save").click({ button: "left", clicks: 1 });
    ```
  </TabItem>
  <TabItem label="Python">

    ```python
    print(await terminal.get_by_text("Save").locations())
    await terminal.get_by_text("Save").expect()
    await terminal.get_by_text("Save").click(button="left", clicks=1)
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust
    use tui_test::{LocatorClickOptions, MouseButton, MouseOptions};

    println!("{:?}", terminal.get_by_text("Save").locations()?);
    terminal.get_by_text("Save").expect()?;
    terminal
        .get_by_text("Save")
        .click_with(LocatorClickOptions {
            mouse: MouseOptions {
                button: MouseButton::Left,
                ..Default::default()
            },
            clicks: 1,
            ..Default::default()
        })?;
    ```
  </TabItem>
  <TabItem label="Go">

    ```go
    {
        value, err := terminal.GetByText("Save", tuitest.TextSelectorOptions{}).Locations()
        if err != nil {
            t.Fatal(err)
        }
        fmt.Println(value)
    }
    if err := terminal.GetByText("Save", tuitest.TextSelectorOptions{}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    if err := terminal.GetByText("Save", tuitest.TextSelectorOptions{}).Click(tuitest.LocatorClickOptions{MouseButtonOptions: tuitest.MouseButtonOptions{Button: tuitest.Left}, Clicks: tuitest.Ptr(uint32(1))}); err != nil {
        t.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="CLI">

    ```sh
    tui-test find text "Save"
    tui-test expect text "Save"
    tui-test click text "Save"
    ```
  </TabItem>
</Tabs>

In JavaScript use `terminal.getByText("Save")`; in Python use
`terminal.get_by_text("Save")`. Rust and Go expose the same operations through
`get_by_text` and `GetByText`.

## Regular expressions and whitespace

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    await terminal.getByText("item \\d+", { regex: true }).expect();
    console.log(
      await terminal
        .getByText("first second", { whitespace: "normalize" })
        .locations(),
    );
    ```
  </TabItem>
  <TabItem label="Python">

    ```python
    await terminal.get_by_text("item \\d+", regex=True).expect()
    print(await terminal.get_by_text("first second", whitespace="normalize").locations())
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust
    use tui_test::{TextSelector, WhitespaceMode};

    terminal
        .get_by_text(TextSelector {
            text: "item \\d+".into(),
            regex: true,
            ..Default::default()
        })
        .expect()?;
    println!(
        "{:?}",
        terminal
            .get_by_text(TextSelector {
                text: "first second".into(),
                whitespace: WhitespaceMode::Normalize,
                ..Default::default()
            })
            .locations()?
    );
    ```
  </TabItem>
  <TabItem label="Go">

    ```go
    if err := terminal.GetByText("item \\d+", tuitest.TextSelectorOptions{Regex: true}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    {
        value, err := terminal.GetByText("first second", tuitest.TextSelectorOptions{Whitespace: tuitest.Normalize}).Locations()
        if err != nil {
            t.Fatal(err)
        }
        fmt.Println(value)
    }
    ```
  </TabItem>
  <TabItem label="CLI">

    ```sh
    tui-test expect text 'item \d+' --regex
    tui-test find text "first second" --whitespace normalize
    ```
  </TabItem>
</Tabs>

Text queries accept literal text or a regular expression. Whitespace matching
is `exact` or `normalize`. Add `--full` to search scrollback as well as the
live screen.

## Style locators

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    await terminal
      .getByText("Ready")
      .getByStyle({ foreground: "green", bold: true })
      .expect();
    await terminal.getByText("Ready").getByStyle({ bold: false }).expect();
    ```
  </TabItem>
  <TabItem label="Python">

    ```python
    from tui_test import TextStyle

    await terminal.get_by_text("Ready").get_by_style(TextStyle(foreground="green", bold=True)).expect()
    await terminal.get_by_text("Ready").get_by_style(TextStyle(bold=False)).expect()
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust
    use tui_test::TextStyle;

    terminal
        .get_by_text("Ready")
        .get_by_style(TextStyle {
            foreground: Some("green".into()),
            bold: Some(true),
            ..Default::default()
        })
        .expect()?;
    terminal
        .get_by_text("Ready")
        .get_by_style(TextStyle {
            bold: Some(false),
            ..Default::default()
        })
        .expect()?;
    ```
  </TabItem>
  <TabItem label="Go">

    ```go
    if err := terminal.GetByText("Ready", tuitest.TextSelectorOptions{}).GetByStyle(tuitest.TextStyle{Foreground: tuitest.Ptr("green"), Bold: tuitest.Ptr(true)}, tuitest.StyleSelectorOptions{}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    if err := terminal.GetByText("Ready", tuitest.TextSelectorOptions{}).GetByStyle(tuitest.TextStyle{Bold: tuitest.Ptr(false)}, tuitest.StyleSelectorOptions{}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="CLI">

    ```sh
    tui-test expect text "Ready" --fg green --bold
    tui-test expect text "Ready" --bold=false
    ```
  </TabItem>
</Tabs>

Style fields include foreground, background, bold, dim, italic, underline style
and color, inverse, hidden, strikethrough, and blink. Boolean options can require
either true or false.

The libraries also create style-only locators, such as
`terminal.getByStyle({ bold: true })`. Root style selectors find contiguous
runs within each row. A chained style selector with the default `within`
direction checks the whole candidate match. Style checks skip blank cells
when the match contains visible text.

## Hyperlink locators

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    await terminal.getByText("Docs").getByLink("https://example.com/docs").expect();
    await terminal.getByText("Plain text").getByLink("").expect();
    ```
  </TabItem>
  <TabItem label="Python">

    ```python
    await terminal.get_by_text("Docs").get_by_link("https://example.com/docs").expect()
    await terminal.get_by_text("Plain text").get_by_link("").expect()
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust
    terminal
        .get_by_text("Docs")
        .get_by_link("https://example.com/docs")
        .expect()?;
    terminal
        .get_by_text("Plain text")
        .get_by_link("")
        .expect()?;
    ```
  </TabItem>
  <TabItem label="Go">

    ```go
    if err := terminal.GetByText("Docs", tuitest.TextSelectorOptions{}).GetByLink("https://example.com/docs", tuitest.LinkSelectorOptions{}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    if err := terminal.GetByText("Plain text", tuitest.TextSelectorOptions{}).GetByLink("", tuitest.LinkSelectorOptions{}).Expect(tuitest.LocatorExpectOptions{}); err != nil {
        t.Fatal(err)
    }
    ```
  </TabItem>
  <TabItem label="CLI">

    ```sh
    tui-test expect text "Docs" --link "https://example.com/docs"
    tui-test expect text "Plain text" --link ""
    ```
  </TabItem>
</Tabs>

Links match exact OSC 8 targets, not the visible spelling of a URL.
An empty URI requires no link. Every cell, including spaces, must satisfy
the link constraint.

JavaScript's `getByLink`, Python's and Rust's `get_by_link`, and Go's
`GetByLink` create link-only locators. Root selectors find per-row runs;
chained selectors with `within` check whole matches.

## Combine and filter locators

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    const label = terminal.getByText("Documentation");
    const link = terminal.getByLink("https://example.com/docs");
    const linkedCells = label.and(link);
    const either = label.or(terminal.getByText("Help"));
    const containsLink = label.filter({ has: link });
    const withoutOldText = label.filter({ hasNot: terminal.getByText("old") });
    ```
  </TabItem>
  <TabItem label="Python">

    ```python
    label = terminal.get_by_text("Documentation")
    link = terminal.get_by_link("https://example.com/docs")
    linked_cells = label.and_(link)
    either = label.or_(terminal.get_by_text("Help"))
    contains_link = label.filter(has=link)
    without_old_text = label.filter(has_not=terminal.get_by_text("old"))
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust
    let label = terminal.get_by_text("Documentation");
    let link = terminal.get_by_link("https://example.com/docs");
    let linked_cells = label.and(&link)?;
    let either = label.or(&terminal.get_by_text("Help"))?;
    let contains_link = label.filter(tui_test::LocatorFilterOptions {
        has: Some(link),
        ..Default::default()
    })?;
    let without_old_text = label.filter(tui_test::LocatorFilterOptions {
        has_not: Some(terminal.get_by_text("old")),
        ..Default::default()
    })?;
    ```
  </TabItem>
  <TabItem label="Go">

    ```go
    label := terminal.GetByText("Documentation", tuitest.TextSelectorOptions{})
    link := terminal.GetByLink("https://example.com/docs", tuitest.LinkSelectorOptions{})
    linkedCells, err := label.And(link)
    if err != nil {
        t.Fatal(err)
    }
    either, err := label.Or(terminal.GetByText("Help", tuitest.TextSelectorOptions{}))
    if err != nil {
        t.Fatal(err)
    }
    containsLink, err := label.Filter(tuitest.LocatorFilterOptions{Has: link})
    if err != nil {
        t.Fatal(err)
    }
    withoutOldText, err := label.Filter(tuitest.LocatorFilterOptions{
        HasNot: terminal.GetByText("old", tuitest.TextSelectorOptions{}),
    })
    if err != nil {
        t.Fatal(err)
    }
    fmt.Println(linkedCells, either, containsLink, withoutOldText)
    ```
  </TabItem>
</Tabs>

`and` keeps shared cells; `or` combines cells without duplicates. Adjacent cells
merge within each physical row, even across original matches. Gaps and row
breaks split runs. Counts and clicks use these cell runs, not DOM elements.
Text retains exact whitespace.

`filter` accepts locators. `has` requires a match inside the candidate;
`hasNot` requires none. Both apply when supplied, and an inner match may cover
the whole candidate. A partially linked word illustrates the difference:
`filter({ has: link })` keeps the whole word, a chained `getByLink` rejects it,
and `and(link)` keeps only linked cells.

Use operands from the same client. Composition leaves them unchanged and reads
one fresh snapshot when resolved. Selection order matters:
`a.first().and(b)` can differ from `a.and(b).first()`. Errors, including a failed
`unique()`, propagate. If any branch uses `full`, the whole query includes
scrollback.

Python spells these methods `and_`, `or_`, and `filter(has=..., has_not=...)`;
Go uses `And`, `Or`, and `Filter`. Rust uses `and` and `or`.
The CLI has no expression syntax for these composition operations.

## Select among multiple matches

| Selection | Meaning |
| --- | --- |
| `any()` | Keep all matches. |
| `unique()` | Require exactly one match. |
| `first()` / `last()` | Select the first or last match. |
| `nth(index)` | Select a zero-based match. |

The CLI uses `--match any|unique|first|last` or `--nth N`.
Choose a match explicitly when the same label appears more than once.

## Read match locations and cell spans

`locations()` returns all selected locations; `location()` requires one.
`count()` returns the current count. `all()` creates a locator for each current
match and does not wait. Match results include text, positions, and cell spans.
Coordinates are zero-based terminal cells.

## Wait, assert, click, and highlight

`expect()` waits for a matching locator, and a negative expectation waits for
it to be absent. `wait()` supports visible and hidden states.
`click()` retries, then clicks the middle cell of one match.
Click options select the button, modifiers, click count, and timeout.
`highlight()` marks matches in screenshots and the live monitor.

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">

    ```js
    await terminal.getByText("Loading").expect({ not: true, timeout: 10000 });
    await terminal.getByText("Continue").click({ button: "left", clicks: 1 });
    await terminal.getByText("Done").highlight();
    ```
  </TabItem>
  <TabItem label="Python">

    ```python

    await terminal.get_by_text("Continue").click(button="left", clicks=1)
    await terminal.get_by_text("Done").highlight()
    ```
  </TabItem>
  <TabItem label="Rust">

    ```rust

                button: MouseButton::Left,
    ```

  <TabItem label="Go">

    ```go
        t.Fatal(err)
    }
    if err := terminal.GetByText("Continue", tuitest.TextSelectorOptions{}).Click(tuitest.LocatorClickOptions{MouseButtonOptions: tuitest.MouseButtonOptions{Button: tuitest.Left}, Clicks: tuitest.Ptr(uint32(1))}); err != nil {
        t.Fatal(err)
    }
    if err := terminal.GetByText("Done", tuitest.TextSelectorOptions{}).Highlight(tuitest.WaitOptions{}); err != nil {
    ```

</Tabs>

## Locate text in scrollback

Use `full` to include scrollback. Visible locators follow the selected native
history viewport. Mouse input and historical locator clicks fail while that
viewport shows history; return with `scroll bottom` before clicking.
See [scrollback](/docs/guides/scrollback/).
