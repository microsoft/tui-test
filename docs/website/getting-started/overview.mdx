`tui-test` controls real shell sessions and full-screen terminal apps on Windows,
Linux, and macOS. It sends keyboard and mouse input, reads terminal text and
styles, waits for state changes, and captures screenshots and recordings.

Use the CLI for terminal automation across separate commands. Use the Rust,
Python, JavaScript, or Go API to write tests in your existing test runner.
AI agents can inspect the same terminal state as structured data.

## Get started

1. [Install the CLI or a library](/docs/install/).
2. [Open your first session](/docs/getting-started/first-session/).
3. [Write a test](/docs/getting-started/writing-tests/) and
   [run it locally or in CI](/docs/getting-started/running-tests/).

## Choose an interface

| Interface | Session lifetime | Reference |
| --- | --- | --- |
| CLI | A daemon keeps sessions alive between commands. | [CLI reference](/docs/reference/cli/) |
| Rust | Sessions run in your process. | [Rust](/docs/api/rust/) |
| Python | Async calls operate on in-process sessions. | [Python](/docs/api/python/) |
| JavaScript and TypeScript | Async calls operate on in-process sessions. | [JavaScript](/docs/api/javascript/) |
| Go | Blocking calls operate on in-process sessions. | [Go](/docs/api/go/) |

Library sessions do not require the CLI and cannot be controlled by it.
Go, Python, and JavaScript load the same
[native adapter](/docs/reference/native-library/).

## Guides

Read [sessions](/docs/guides/sessions/) for lifecycle and isolation,
[locators](/docs/guides/locators/) for finding text, styles, and links, and
[keyboard and mouse](/docs/guides/keyboard-and-mouse/) for input.

[Waiting](/docs/guides/waiting/) and [assertions](/docs/guides/assertions/) explain
how to synchronize a test. [Terminal state](/docs/guides/terminal-state/),
[scrollback](/docs/guides/scrollback/), and
[snapshots](/docs/guides/snapshots/) cover what a test can inspect.

Set [configuration](/docs/guides/configuration/) and
[shells and backends](/docs/guides/shells-and-backends/) to match the environment
you want to test. See [reliable tests](/docs/guides/reliable-tests/) and
[examples](/docs/guides/examples/) for common patterns.

## Capture and debugging

Save [screenshots](/docs/tools/screenshots/) or
[recordings](/docs/tools/recordings/), record a scripted
[tape](/docs/tools/tapes/), or watch a session in the
[live monitor](/docs/tools/monitor/).
Use the [trace viewer](/docs/tools/trace-viewer/) and
[failure diagnostics](/docs/tools/failure-diagnostics/) to investigate a failure.
The [AI agent guide](/docs/tools/ai-agents/) covers command schemas and
machine-readable evidence.
