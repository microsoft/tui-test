`tui-test` runs real terminal sessions on Windows, Linux, and macOS. Install the CLI and agent skill for shell scripts, interactive debugging, and AI agent workflows, or install a language library to run the terminal engine directly inside your test suite.

## CLI

The install script downloads the latest stable release for your platform. Releases target `x86_64` and `aarch64` on macOS, Linux, and Windows. Windows ARM64 requires a release newer than `0.1.1`.

<Tabs>
  <TabItem label="macOS and Linux">
    ```sh
    curl -fsSL https://tui-test.dev/install.sh | sh
    ```
  </TabItem>
  <TabItem label="Windows">
    ```powershell
    irm https://tui-test.dev/install.ps1 | iex
    ```
  </TabItem>
</Tabs>

On macOS and Linux, you can also install with Homebrew:

```sh
brew tap microsoft/tui-test https://github.com/microsoft/tui-test
brew install tui-test
```

Prebuilt archives for each supported platform are available on [GitHub Releases](https://github.com/microsoft/tui-test/releases).

### Check the installation

```sh
tui-test --version
```

`--version` (or `-V`) prints the `tui-test` version along with the bundled terminal emulator and PTY dependency versions, including the bundled Microsoft ConPTY version on Windows. Add `--json` for machine-readable output. If your shell cannot find `tui-test`, open a new terminal or verify that the install directory is on `PATH`.

## Agent skill

Install the `tui-test` skill for coding agents using Vercel's [`skills`](https://github.com/vercel-labs/skills) CLI:

```sh
npx skills add microsoft/tui-test --skill tui-test
```

Or install the embedded skill interactively from the `tui-test` CLI:

```sh
tui-test skill --add
```

See [AI agents](/docs/getting-started/ai-agents/) for agent workflows, prompt options, and JSON schema commands.

## Libraries

Each library runs the terminal engine in-process.

<Tabs syncKey="example-language">
  <TabItem label="JavaScript">
    Requires Node.js 20 or newer. Keep optional dependencies enabled during installation.

    ```sh
    npm install @microsoft/tui-test
    ```

    The package is ESM only. Bun and Deno work on a best-effort basis; Deno 2 requires a local `node_modules` directory and `--allow-ffi`. See the [JavaScript and TypeScript API](/docs/api/javascript/).
  </TabItem>
  <TabItem label="Python">
    Requires Python 3.8 or newer.

    ```sh
    pip install tui-test
    ```

    See the [Python API](/docs/api/python/).
  </TabItem>
  <TabItem label="Rust">
    Requires Rust 1.90 or newer. The Cargo package is `tui-test-rs` and exports the `tui_test` crate.

    ```sh
    cargo add tui-test-rs@0.1.1
    ```

    Alacritty is enabled by default. Enable `ghostty`, `rio`, or `xtermjs` for additional terminal backends, and `recording-raster` (or `recording-font-jetbrains-mono*` for bundled fonts) for APNG, GIF, and MP4 output. See the [Rust API](/docs/api/rust/) and [docs.rs](https://docs.rs/tui-test-rs/latest/tui_test/).
  </TabItem>
  <TabItem label="Go">
    Requires Go 1.26 or newer.

    ```sh
    go get github.com/microsoft/tui-test/bindings/go@v0.1.1
    ```

    See the [Go API](/docs/api/go/).
  </TabItem>
</Tabs>

### Custom native library path

When running against a local source checkout, testing a custom engine binary, or running Go where the user cache directory (`os.UserCacheDir()`) cannot be written, set `TUI_TEST_NATIVE_LIBRARY` to the absolute path of `libtui_test_ffi.so`, `libtui_test_ffi.dylib`, or `tui_test_ffi.dll`. The shared library must match your language package's release version and target platform. See [`crates/tui-test-ffi/README.md`](https://github.com/microsoft/tui-test/blob/main/crates/tui-test-ffi/README.md#build-and-use) for local source builds.

### Requirements

Prebuilt libraries for JavaScript, Python, and Go support `x86_64` and `arm64` on macOS, Linux, and Windows. For Windows ARM64, use a package newer than `0.1.1`. On Linux, prebuilt packages require glibc 2.28+ or musl 1.2+. `tui-test-rs` compiles from source with Cargo against your target's standard library.
