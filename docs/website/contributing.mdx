## Build from source

Clone the repository and install Rust 1.90 or newer. Building the CLI and shared FFI library also requires Zig 0.16 for the Ghostty backend.

```sh
cargo build -p tui-test-cli -p tui-test-ffi
```

The shared native library is written to `target/debug/libtui_test_ffi.so` on Linux, `target/debug/libtui_test_ffi.dylib` on macOS, or `target/debug/tui_test_ffi.dll` on Windows. Set `TUI_TEST_NATIVE_LIBRARY` to its absolute path when running the Go, Python, or JavaScript bindings from a source checkout.

On musl Linux, disable static CRT linkage so Cargo can link a shared library:

```sh
RUSTFLAGS="${RUSTFLAGS:-} -C target-feature=-crt-static" cargo build -p tui-test-ffi
```

For the JavaScript package, run `npm ci && npm run build` inside `bindings/js`. For Python wheel builds, see the [Python API](/docs/api/python/#build-from-source). Internal C ABI and vendored xterm.js maintenance notes live in [`crates/tui-test-ffi/README.md`](https://github.com/microsoft/tui-test/blob/main/crates/tui-test-ffi/README.md) and [`crates/tui-test/assets/xtermjs/README.md`](https://github.com/microsoft/tui-test/blob/main/crates/tui-test/assets/xtermjs/README.md).

## Run repository checks

The [CI workflow](https://github.com/microsoft/tui-test/blob/main/.github/workflows/ci.yml) validates formatting, generated bindings, linting, and tests across Linux, macOS, and Windows:

```sh
cargo fmt --all -- --check
cargo run --locked -p tui-test-bindgen -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo clippy -p tui-test-rs --all-targets --no-default-features -- -D warnings
cargo test --workspace -- --test-threads=1
cargo test -p tui-test-rs --features recording-font-jetbrains-mono-styles -- --test-threads=1
npm test --prefix .github/scripts
```

CI also verifies C11/C++17 header compilation, Go `gofmt`/`go vet`/race tests, embedded Go consumer packaging, Python `unittest`, JavaScript Node tests, and standalone `trace-viewer` checks.

## Update documentation

Website documentation lives under `docs/website/` in `microsoft/tui-test`:

- `docs/website/navigation.json` defines the documentation entry route, `/docs` redirects, and sidebar sections and slugs. Adding, moving, or renaming documentation pages only requires updating `docs/website/` in `microsoft/tui-test`; the website repository reads this navigation file automatically during sync.
- `docs/website/assets/` holds static documentation assets published at `/docs-assets/`. Regenerate the interactive trace example after trace-viewer changes with `node trace-viewer/scripts/docs-example.mjs`.
- Every `.mdx` page requires `title` and `description` in its YAML frontmatter. Use `/docs/.../` for internal documentation links and full GitHub URLs for repository source files.
- For multi-language examples, use Starlight `<Tabs syncKey="example-language">` with exact tab labels `JavaScript`, `Python`, `Rust`, `Go`, and `CLI`. Leave OS-only tabs and single-language API pages unsynchronized.

Run `npm test --prefix .github/scripts` to validate `navigation.json`, slugs, tab labels, and internal documentation links locally. To preview the rendered Starlight site from a sibling [`tui-test-website`](https://github.com/cpendery/tui-test-website) checkout:

```sh
npm run sync -- --source ../tui-test
npm run check
npm run build
```
